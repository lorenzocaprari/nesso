# AGENTS.md

Instructions for coding agents on nesso. Product behavior is in [docs/usage.md](docs/usage.md). The short intro is [README.md](README.md). Contributor workflow is in [CONTRIBUTING.md](CONTRIBUTING.md); follow that file instead of copying it.

## Project

Nesso is a Linux-native C++26 CLI for semantic search over local text (`nesso grep`, `nesso index`, `nesso search`). Embeddings come from an ONNX MiniLM model. Ranking is a brute-force scan. The toolchain is Conan 2, CMake 4.2+ (`CMakeLists.txt`), and Ninja. Profiles live in `conan/profiles/`. Contributor scripts live under `scripts/`; pipeline helpers under `scripts/ci/`; release and packaging helpers under `packaging/scripts/` (`scripts/README.md`).

## Commands

Run these from the repository root. Profiles: `gcc-26` (CI Release, `-flto=auto`), `gcc-26-dev` (local Release, no LTO, `user.nesso:link_jobs=1`), `gcc-26-debug` (Debug, ASan, UBSan, `-fno-sanitize-recover=all`), `gcc-26-asan-release` (nightly `-O2` ASan/UBSan), `gcc-26-fuzz`, `gcc-26-armv8`, `gcc-26-el9` (EL9 Release, GCC Toolset 16.2.1), `gcc-26-el9-armv8`, `clang-26` (Clang 23.1.6, libstdc++), `clang-26-asan`, `clang-26-tsan` (local ThreadSanitizer, `ctest -L tsan`), and `code-coverage`. Local low-RAM paths (Debug with `-c user.nesso:link_jobs=1`, `gcc-26-dev`, optional `gcc-26` + `NESSO_REPRODUCIBLE=1`) are in [docs/building.md](docs/building.md). `gcc-26-dev`, `gcc-26-asan-release`, `clang-26-asan`, and `clang-26-tsan` are not build-env-hash inputs.

`nesso_options` in `CMakeLists.txt` is the INTERFACE target every nesso target links: the libraries, the `nesso` binary, the tests, the fuzz harnesses, and `nesso_bench`. It requires `cxx_std_26` with compiler extensions off and holds the warning set. `-Werror` is the CMake option `NESSO_WERROR`, default OFF. No profile sets `user.nesso:werror`. `conanfile.py` copies that conf into `NESSO_WERROR`. `conan build` runs generators again, so `-c user.nesso:werror=True` has to be on both `conan install` and `conan build` or the build step clears it. The same dual-command rule applies to `-c user.nesso:link_jobs=N` (Ninja link pool; unset in CI). `.github/workflows/ci.yml` sets `CONAN_WERROR_ARGS` to that `-c` and appends `$CONAN_WERROR_ARGS` unquoted on every `conan install` and `conan build`. The coverage step and the fuzz-test workflow set `NESSO_WERROR=1`. Optimization, sanitizer, LTO, and visibility flags stay in `user.nesso:cxxflags` and do not reach the ONNX Runtime build. `gcc-26-debug` passes `-fno-sanitize-recover=all` next to `-fsanitize=address,undefined`, so a local debug build stops on the first ASan or UBSan error without `UBSAN_OPTIONS`.

```bash
# Conan 2 install. Inside the nesso-build-env image (CONAN_HOME=/opt/conan2) keep --lockfile=conan.lock and --no-remote. Outside that image, drop --no-remote.
# Low-RAM Debug: add -c user.nesso:link_jobs=1 on install and build. Local Release without LTO: use gcc-26-dev (sets link_jobs=1).
# Binary-only: add -o tests=False on install and build (default tests=True; skips test/ including fuzz harnesses in this build).
conan install . -pr:h ./conan/profiles/gcc-26-debug -pr:b default --lockfile=conan.lock --build=missing --no-remote

# Configure and compile the same profile. Debug binary: build/Debug/src/nesso. Release: gcc-26-dev or gcc-26 and build/Release/src/nesso.
conan build . -pr:h ./conan/profiles/gcc-26-debug -pr:b default --lockfile=conan.lock --build=missing --no-remote

# Fetch the default int8 MiniLM into models/. The fp32 gate uses the second argument: ./scripts/fetch-model models-fp32 fp32.
./scripts/fetch-model

# ctest labels unit, integration, and functional, set on the tests added under test/.
ctest --test-dir build/Debug -L unit
ctest --test-dir build/Debug -L integration
ctest --test-dir build/Debug -L functional

# CI adds --output-on-failure and -j "$(nproc)" on every ctest invocation, including scripts/code-coverage.
# The bdd test runs godog scenarios concurrently, one per logical CPU (runtime.NumCPU()), with NESSO_THREADS=1 unless a scenario sets it.

# Local gate. clang-tidy needs compile_commands.json. scripts/clang-tidy drops GCC-only -W flags and Clang @*.modmap args from that database before analysis. Optional NESSO_CLANG_TIDY_BUILD_DIR selects a compile DB. CI's clang-tidy job configures with clang-26 so the compile DB matches the Clang build lane. portability-restrict-system-includes allowlists stdlib, OS, and dependency angle includes in .clang-tidy (comma-separated GlobList). scripts/clang-tidy-diff lints only the diff against the main remote-tracking branch; CI still runs the full-tree script. With NESSO_CLANG_TIDY_CACHE set (CI sets build/clang-tidy-cache), scripts/clang-tidy runs `go run -C scripts/ci . clang-tidy-cache` and skips units already found clean: the key is the -E -C -dD output, the raw bytes of every repository file the preprocessor entered, the compile arguments, the clang-tidy version, and every .clang-tidy file. Only clean units are recorded. Pull requests restore main's cache; only a push to main saves it. Coverage floors are REQUIRED_* in scripts/code-coverage.
# scripts/lint --format-only is clang-format and cmake-format. --hygiene-only is the whitespace, line-ending, YAML, merge-marker, and large-file hooks.
# scripts/actionlint and scripts/zizmor download pinned Linux binaries, verify sha256, and lint .github/workflows.
bash scripts/lint
bash scripts/actionlint
bash scripts/zizmor
bash scripts/clang-tidy
./scripts/code-coverage conan/profiles/code-coverage

# AFL++ harnesses nesso_fuzz_parser and nesso_fuzz_tokenizer (conan/profiles/gcc-26-fuzz).
./scripts/fuzz-test

# fp32 determinism gate. --input must already exist. CI writes determinism-input.log for this command.
./scripts/check-determinism --binary build/Release/src/nesso --model-dir models-fp32 --input determinism-input.log

# End-to-end bench. CI pull requests run 1k and 10k and fail the bench job on a regression
# against the latest main baseline. Pushes to main and the nightly schedule also run 100k.
python3 scripts/bench
python3 scripts/bench-compare
# Local index and first-search measurement on a generated log directory.
python3 scripts/bench --dataset logdir
```

## Misreads

- `NESSO_REQUIRE_MODEL=1` fails model-backed tests instead of skipping them, and drops Catch2 `--allow-running-no-tests` (`test/CMakeLists.txt`). `NESSO_REQUIRE_BDD=1` turns a missing Go toolchain into a configure error (`test/functional/CMakeLists.txt`). CI sets both. Unset, missing `models/` or a missing `go` binary skips those tests.
- The fp32 step and the default int8 policy gate the `determinism` job. A pull request sets `NESSO_DETERMINISM_MODE=pr` (`scripts/check-determinism --mode pr`: 256-line input, 2 runs, 2 index runs). Pushes to `main`, the nightly schedule, and `workflow_dispatch` set that variable to `full` (3500-line input, 10 runs, `--index-runs 3`). The int8 step with `NESSO_THREADS=$(nproc)` is `continue-on-error` and report-only (`.github/workflows/ci.yml`). The release workflow calls the script with `--runs 10` and `--index-runs 3` and does not set the mode.
- `conan install` writes `CMakeUserPresets.json` at the repository root. It is generated, `.gitignore` does not list it, and it stays uncommitted. `build/` is ignored, which covers `build/<Config>/generators/CMakePresets.json`.
- `scripts/ci/build-env-hash` hashes each Dockerfile and every path it copies. `conanfile.py` enters the hash as the resolved dependency spec, not as raw text. The amd64 image copies `conan.lock`, `conan/global.conf`, `.devcontainer/requirements.txt`, `conan/profiles/gcc-26`, `conan/profiles/gcc-26-debug`, `test/functional/go.mod`, and `test/functional/go.sum`. The arm64 image copies `conan.lock`, `conan/global.conf`, `conan/profiles/gcc-26-armv8`, `test/functional/go.mod`, and `test/functional/go.sum`. Changing one of those makes `prepare-image-amd64` or `prepare-image-arm64` rebuild `ghcr.io/<owner>/nesso-build-env:deps-<hash>` (the arm64 tag appends `-arm64`). That job's timeout is 360 minutes. `clang-26`, `clang-26-asan`, `clang-26-tsan`, `code-coverage`, `gcc-26-fuzz`, `gcc-26-dev`, and `gcc-26-asan-release` are not copied, so editing only those profiles does not rebuild the image. Both images install stress-ng, zstd, and ccache, and set `GOMODCACHE` to `/opt/go/pkg/mod` so a GitHub Actions `HOME` override does not hide the godog modules. The amd64 image also installs AFL++, lld-21, llvm-21, lld-23, llvm-23, and GNU time (`/usr/bin/time`) in that post-Conan layer. afl++, Clang 23.1.6 from apt.llvm.org (`llvm-toolchain-resolute-23`, fingerprint `6084 F3CF 814B 57C1 CF12 EFD5 15CF 4D18 AF4F 7421`), the LLVM 21 compiler-rt symlinks AFL++ still needs, and the LLVM 23 compiler-rt symlinks (`asan`, `ubsan`, `tsan`, `tsan_cxx`, `fuzzer`) stay in the compiler layer above the Conan installs, so adding the linkers and GNU time does not rebuild those layers. The arm64 image does not install AFL++, lld, llvm, or GNU time. `bench` is amd64-only.
- `build-gcc-26-amd64`, `build-gcc-26-debug-amd64`, `build-gcc-26-arm64`, and `build-el9-amd64` set `CMAKE_C_COMPILER_LAUNCHER` and `CMAKE_CXX_COMPILER_LAUNCHER` to ccache, with `CCACHE_MAXSIZE` at 150M. The EL9 lane key is `ccache-<runner.arch>-el9-gcc-16-Release-<github.sha>`. `coverage` does not use ccache, so gcov output is not served from the cache. `conanfile.py` copies a set launcher into the CMake toolchain and always sets `CMAKE_CXX_SCAN_FOR_MODULES` off: the tree has no C++ modules; GCC 14+ would add `-fmodules-ts` (ccache refuses it), and a Clang configure-only compile DB would otherwise reference missing `@*.modmap` files. The cache key is `ccache-<runner.arch>-<lane>-<github.sha>`. Pull requests restore with the lane prefix. Only a push to `main` saves. `fuzz-test` does not wrap `afl-clang-lto`. The statistics step runs under bash and fails the job when ccache records an uncacheable compilation.
- `prepare-image-amd64` exports BuildKit cache to `ghcr.io/<owner>/nesso-build-env:buildcache` and `prepare-image-arm64` exports `:buildcache-arm64`, both `mode=max`, when that image is rebuilt. The Conan installs are Dockerfile layers above ccache, Go, stress-ng, and zstd, and on amd64 also above AFL++, lld-21, llvm-21, lld-23, llvm-23, and GNU time, so a change to those tools does not rebuild the dependency layers. Those jobs free disk only when they rebuild and the runner has under 40 GiB free. They then delete `/usr/local/lib/android`, `/usr/share/dotnet`, and `/opt/ghc` in parallel. They do not apt-purge or prune Docker images.
- `prepare-image-el9-amd64` and `prepare-image-el9-arm64` publish Rocky Linux 9 images to `ghcr.io/<owner>/nesso-build-env-el9`. `scripts/ci/build-env-hash el9-amd64` covers `.devcontainer/Dockerfile.el9`, `.devcontainer/requirements.txt`, `conan.lock`, `conan/global.conf`, `conan/profiles/gcc-26-el9`, `test/functional/go.mod`, and `test/functional/go.sum`. `el9-arm64` covers `.devcontainer/Dockerfile.el9.arm64` and `conan/profiles/gcc-26-el9-armv8` instead of the amd64 profile. `conanfile.py` is the resolved dependency spec, same as the Ubuntu hash. The tags are `deps-<hash>` and `deps-<hash>-arm64`. The BuildKit cache tags on that repository are `buildcache` and `buildcache-arm64` (`mode=max`). The Rocky base is pinned by digest. CMake 4.4.5 is the pinned tarball (EL9 ships 3.31; this project requires 4.2). The toolset package is `gcc-toolset-16-gcc-16.2.1-1.4.el9_9`. Host profiles `conan/profiles/gcc-26-el9` and `conan/profiles/gcc-26-el9-armv8` set `compiler.version=16`. The default build profile stays `compiler.version=15` so tool_requires keep Conan Center package ids; `packaging/scripts/build-release-binary` writes that profile when `NESSO_ABI_BASELINE` is set. Ubuntu images stay on GCC 15: resolute's `gcc-16` package is the 20260322 trunk snapshot, not 16.2. Python is 3.12. Ninja comes from CRB. ccache comes from EPEL, in the layer after the Conan install, with Go and zstd. `prepare-image-el9-amd64` runs on every Pipeline event. `prepare-image-el9-arm64` skips a docs-only pull request. The image jobs do not compile nesso, and neither `needs` the Ubuntu image jobs. `build-el9-amd64` needs `prepare-image-el9-amd64` and runs when `changes` reports code. It sets `NESSO_ABI_BASELINE` and calls `packaging/scripts/build-release-binary`, which selects `conan/profiles/gcc-26-el9` and runs `scripts/check-abi-baseline`. The job then runs `nesso -V` and `ctest -L unit` except `package_deb_test`, which needs `dpkg-deb`. The image's ccache 4.5 stats are `Hits: N / total`, not `Cacheable calls`. There is no EL9 arm64 build lane. Package and Release pull `nesso-build-env-el9` for the release binary. The `.deb` is packed on the Ubuntu runner. Dependabot ignores a semver-major bump of `rockylinux`.
- All four build-env Dockerfiles append `conan/global.conf` to `$CONAN_HOME/global.conf` before the first `conan install`. It sets `core.sources:download_urls` to `origin`, then the `conan-sources` release of [nesso-vendor](https://github.com/lorenzocaprari/nesso-vendor): when a recipe's source URL fails, Conan downloads `<sha256>` and `<sha256>.json` from there and checks the recipe's sha256. The upstream onnxruntime repository on GitHub returns 404 since 18 Nov 2026; nesso-vendor's onnxruntime 1.18.1 archive is byte-identical to the original (sha256 `480ff5d2…`, ConanCenter's pin) and a script in nesso-vendor rebuilds it from Software Heritage. A local cache without the onnxruntime package needs the same line in its own `global.conf` ([docs/building.md](docs/building.md)).
- `conan/profiles/clang-26` keeps `compiler=gcc` and `compiler.version=15` so `--no-remote` reuses the `gcc-26` packages baked into the image. `compiler=clang` changes package ids and rebuilds dependencies from source. The compiler is Clang 23.1.6 (`clang-23` / `clang++-23`, libstdc++). `clang-26-asan` and `clang-26-tsan` use the same compiler. Pipeline `clang-tidy` configures with `clang-26` and checks that `compile_commands.json` names `clang++-23` and that `clang++-23 --version` reports 23.1.6. `-modernize-use-trailing-return-type` stays disabled. clang-tidy 23 also disables `cppcoreguidelines-pro-bounds-avoid-unchecked-container-access`, `readability-trailing-comma`, and `llvm-use-ranges`; the reasons are in `.clang-tidy`.
- The godog test is named `bdd` and its label is `functional`. `ctest -L bdd` selects nothing. CI runs the `unit`, `integration`, and `functional` labels. `test-gcc-26-amd64` and `test-gcc-26-arm64` run all three in one job. `.github/workflows/clang-asan-nightly.yml` does too. `test-gcc-26-debug-amd64` runs unit and integration. `test-gcc-26-debug-amd64-functional` runs functional alone: on a no-image pull request that suite is the wall-clock tail, and the bdd test already uses every logical CPU.
- `scripts/lint` runs pre-commit, `scripts/check-versions`, and `scripts/check-agent-docs`. `--format-only` runs the `clang-format` and `cmake-format` hooks. `--hygiene-only` runs `trailing-whitespace`, `end-of-file-fixer`, `mixed-line-ending`, `check-merge-conflict`, `check-added-large-files`, and `check-yaml`. cppcheck is `scripts/cppcheck`, after a Release configure. The `cppcheck` job runs that script. `scripts/lint` does not run cppcheck, actionlint, or zizmor. The `lint` job runs on the runner, with no build image. Its steps are format, hygiene, versions, agent docs, actionlint (`scripts/actionlint`, 1.7.12, no shellcheck or pyflakes), zizmor (`scripts/zizmor`, 1.31.1, regular persona), and the Pipeline gate needs check (`go run -C scripts/ci . ci-gate-needs`). Both download the pinned binary and check sha256. zizmor uses `GITHUB_TOKEN` for online audits when it is set, and `--offline` otherwise. Pull requests add a dependency-review step in that same job (config `.github/dependency-review-config.yml`): moderate and above, scopes runtime, development, and unknown, and a detected license outside the Apache-2.0 allow list. The check name stays `lint`. The graph covers Actions, `test/functional/go.mod`, and `.devcontainer/requirements.txt`. `conanfile.py`, `conan.lock`, `scripts/ci/go.mod`, and `test/scripts/go.mod` (no requirements) are not reviewed. Pushes, the nightly schedule, and `workflow_dispatch` skip that step.
- `scripts/code-coverage` adds `--no-remote` and exports `NESSO_REQUIRE_MODEL=1` only when `CI=true`. Modes: default/`full` (build+test+capture+floors), `build`, `test` (`--ctest-arg` repeatable), `capture`, and `merge` (`--merge` traces then the same `--remove` and floors). The fuzz-test workflow sets `NESSO_WERROR=1`. A local run leaves `NESSO_WERROR` unset. When it is `1`, `scripts/code-coverage` passes `-c user.nesso:werror=True` on its `conan build` (that command regenerates the toolchain; the script has no `conan install`), and `scripts/fuzz-test` passes the same `-c` on its `conan install` and does not call `conan build`. `.clusterfuzzlite/build.sh` does not pass `-Werror`. Every `conan install` and `conan build` in `.github/workflows/ci.yml` appends unquoted `$CONAN_WERROR_ARGS` (`-c user.nesso:werror=True`): clang-tidy and cppcheck on install, and `gcc-26`, `gcc-26-debug`, and `gcc-26-armv8` on install and build. Pipeline coverage is `coverage-build` (instrumented tree; `ci-build-archive pack-coverage` keeps gcov note files), `coverage-unit` (ctest except `bdd`), `coverage-bdd` (four feature-file shards via `NESSO_GODOG_PATHS`), and `coverage` (merge floors, Codecov, patch). Those jobs set `NESSO_REQUIRE_BDD=1` and `NESSO_WERROR=1` on the build lane.
- Pull requests add a patch-coverage gate to the `coverage` merge job after the tree-wide floor. `scripts/ci` (`patch-coverage`) reads the lcov trace the merge already wrote and the `src/` diff against the pull request base. The job fails when fewer than 80% of the changed executable lines are hit, and the job summary lists the misses as `file:line`. A diff with no executable `src/` lines passes, including docs, CI, and tests. Pushes to `main`, the nightly schedule, and `workflow_dispatch` skip the gate. The gate does not install a tool and does not change the build-env image.
- On a pull request and on a push to `main`, `coverage` uploads `build/coverage/coverage.cleaned` to Codecov after the floor script. Same-repo runs use GitHub OIDC (`id-token: write` on that job). Fork pull requests upload with no token; the action tags those branches so Codecov accepts a public tokenless upload. Dependabot turns OIDC off, because that actor does not get an OIDC token, and uses a Dependabot `CODECOV_TOKEN` only when one is set. `fail_ci_if_error` is false, so a rejected upload does not fail the job. The nightly schedule and `workflow_dispatch` do not upload. `.github/codecov.yml` marks Codecov's project and patch statuses informational. The floors in `scripts/code-coverage` stay the gate.
- `test-gcc-26-amd64`, `test-gcc-26-debug-amd64`, `test-gcc-26-debug-amd64-functional`, and `test-gcc-26-arm64` pass `--output-junit` to ctest. `scripts/ci` (`junit-summary`) appends failing test names and output to the job summary. The XML is uploaded as `junit-<job id>`.
- The `bench` job compares only tiers present in both the run and the committed `bench/baseline.json`. Pull requests omit 100k. A missing baseline file fails the job. `scripts/bench-compare` still warns and exits 0 when the file is absent, which is the local path; CI checks that the file exists before calling it. CI allows wall time up to 1.35× and peak RSS up to 1.15× (`NESSO_BENCH_WALL_TOLERANCE` `0.35`, `NESSO_BENCH_RSS_TOLERANCE` `0.15`). Local compare stays at 15% against the same file. The job also runs the 4000-line grep with `NESSO_THREADS=1` and `NESSO_THREADS=4` and fails unless the speedup reaches `threadScaleMinRatio` in `scripts/ci` (`bench-scale`). That minimum is enforced only when both runs record `threadScaleCPU` as `cpuModel` (the AWS-hosted runners it was calibrated on); on any other CPU `bench-scale` prints the speedup and a `::warning::` and exits 0. `--cpu ''` enforces it on every CPU. `bench-summary` writes lines per second for each tier and that ratio to the job summary. `go run -C scripts/ci . bench-baseline` rewrites `bench/baseline.json` from one or more result files, keeping the slower wall time of each tier. No benchmark history is recorded; `bench/baseline.json` is the only stored result. That sample is the Ubuntu GCC 15 Release binary (`gcc-26` on `build-gcc-26-amd64`). EL9 release builds use GCC Toolset 16.2.1, and the Clang lanes and clang-tidy use Clang 23.1.6. Ubuntu 26.04 CI stayed on GCC 15. A later move of this baseline is not that toolchain switch. The 100k tier stays on non-PR runs of `bench`.
- The Pipeline job `eval-retrieval` is the retrieval quality gate. It scores the `build-gcc-26-amd64` binary with nesso-bench at `NESSO_BENCH_REF` (nesso only, dev queries, `auto`/`dense`/`lexical`, `--jobs 4`) and uploads `eval-pipeline`. A pull request scores the merge-base Release binary on the same runner and fails only on `eval-retrieval-compare --fail-on-worse` (per-query MRR or nDCG@10 worse beyond noise on an unchanged query set). A fallback baseline and a push to `main` only warn. The label `eval-regression-accepted`, read when the job runs, turns a failure into a warning: add it and re-run the job. `.github/workflows/eval-retrieval.yml` stays nightly and manual only: it reuses that commit's `eval-pipeline` for nesso when present, scores grep and BM25, and shows margins.
- AFL++ `fuzz-test` is `.github/workflows/fuzz-test.yml`, not a Pipeline job. It runs on pushes to `main`, on the nightly schedule (`17 3 * * *`), and on `workflow_dispatch`. Pull requests are fuzzed by ClusterFuzzLite (`.github/workflows/cifuzz.yml`). The workflow does not `apt-get`: the amd64 image provides `afl-clang-lto++` (Ubuntu AFL++, built against LLVM 21), `ld.lld-21`, `llvm-ar-21`, and `llvm-ranlib-21`, and the compiler-rt symlinks. `llvm-ar-23` does not archive that bitcode. The seeds stay in `test/fuzz/seeds/parser` and `test/fuzz/seeds/tokenizer`.
- The nightly gate on peak RSS is `.github/workflows/bench-real-log.yml`, on real Loghub prefixes for `index`, `grep`, and `search` (1M HDFS, BGL, and Thunderbird lines), with a ceiling of 1.5 GiB times `(1 + NESSO_BENCH_RSS_TOLERANCE)`.
- Real-log soak is `.github/workflows/bench-real-log.yml`. The nightly default corpora are `hdfs-v1` (cheap smoke) and `thunderbird` (peak-RSS / wall canary). `bgl` stays available via the `corpora` workflow input / `scripts/bench --corpora`. Line counts are per corpus (`REAL_LOG_DEFAULT_LINES` in `scripts/bench`); `--lines` overrides all. The workflow passes `--timeout 1200` per command as a hang guard. The logs come from nesso-bench's fetch-loghub script (nesso has no copy): the workflow checks nesso-bench out at `NESSO_BENCH_REF`, which must equal the pins in `.github/workflows/eval-retrieval.yml` and `.github/workflows/ci.yml` (`bench_real_log_test` checks it). Locally, `scripts/bench --dataset real-log` reads `--loghub-dir` (default `build/bench`) and does not download.
- `test-gcc-26-arm64` does not need `prepare-image-amd64`. A code change runs on the arm64 image. A docs-only pull request skips that job. The check name stays `test-gcc-26-arm64`, and GitHub counts the skip as success. `build-gcc-26-arm64` and `prepare-image-arm64` depend only on the arm64 image. Those job ids are the check names. Pipeline does not use a matrix, so a skip never reports an unexpanded `${{ matrix.* }}` name.
- `ci-gate` is the Pipeline job to require in a ruleset. Its check name is `CI gate` (the job `name`, not the id). It `needs` every other job in `.github/workflows/ci.yml`, runs with `if: always()` on `ubuntu-latest`, and finishes by running `go run -C scripts/ci . ci-gate`. A result of `success` passes. `failure` and `cancelled` fail. A `skipped` result passes only when that job was not supposed to run: `changes` succeeded with output `code` false on a pull request (the docs-only path filter). A skip because a needed job failed or was cancelled fails the gate. The `lint` job runs `go run -C scripts/ci . ci-gate-needs`, which fails when a job is missing from `ci-gate`'s `needs` or from its `JOB_RESULTS` lines, or when a job's `if` is not one of those skip shapes.
- A pull request that changes only documentation skips the heavy jobs in `.github/workflows/ci.yml`. Documentation is `*.md`, `docs/`, `LICENSE`, and `.github/ISSUE_TEMPLATE/`. Any other path counts as code. `lint` still runs. It does not use the build image, and its agent-docs step runs `scripts/check-agent-docs`. `clang-tidy` and `cppcheck` run only when the pull request changes code. ## Hard rules

- Commits a coding agent or tool writes are always authored and committed as Lorenzo Caprari <caprarilorenzo5@gmail.com>, with no `Co-authored-by`, `Signed-off-by`, or any other trailer.
- The pull request title matches the pattern in `.github/workflows/pr-title.yml`. [CONTRIBUTING.md](CONTRIBUTING.md) says pull requests are squash-merged and that title becomes the commit on `main`.
- Do not merge, tag, push to `main`, force-push a shared branch, or change repository settings. Lorenzo merges after the Pipeline workflow (`.github/workflows/ci.yml`) is fully green.
- Never lower the `REQUIRED_*` coverage floors in `scripts/code-coverage`, not even to get CI green. If coverage falls below them, add tests. Read the numbers from that file so this doc does not go stale.
- Run `scripts/lint`, `scripts/actionlint`, and `scripts/zizmor` before pushing. Run `scripts/clang-tidy` on new C++.
- One pull request per agreed scope. Anything outside that scope is a note or a follow-up, not extra commits.
- When told to push to an existing branch or pull request, fetch first and push there. Do not open another pull request, and do not overwrite commits you did not author.
- New GitHub Actions use a full commit SHA and a trailing `# vX.Y.Z` comment, as in `.github/workflows/`. `.github/workflows/release.yml` is the exception: its SLSA provenance generators are called by a `vX.Y.Z` tag because those workflows check their own ref. Scorecard Pinned-Dependencies flags those two refs. Leave them on the tag.
- User-facing notes go under `## [Unreleased]` in `CHANGELOG.md`. A release is one squash-merged pull request that bumps `version` in `conanfile.py` and moves that section to `## [X.Y.Z] - YYYY-MM-DD`. Do not bump `version` on any other pull request. After that commit is on `main`, publish the `vX.Y.Z` draft. Do not publish a draft named `Unreleased (bump conanfile.py to release)`: its tag name is `unreleased`, and `.github/workflows/release.yml` does not run for it. `.github/workflows/release-drafter.yml` sets the draft version from `scripts/check-versions`.

## Common pitfalls

| Error | Cause | Fix |
| --- | --- | --- |
| `NESSO_REQUIRE_BDD is set but no go toolchain was found` | `NESSO_REQUIRE_BDD=1` and `go` is missing (`test/functional/go.mod` is Go 1.24) | Install Go, or unset the variable outside CI |
| Model tests skipped while ctest is green | `NESSO_REQUIRE_MODEL` is off, so CMake adds `--allow-running-no-tests` and skips when `models/` is absent | `./scripts/fetch-model`, then configure with `NESSO_REQUIRE_MODEL=1` |
| `ctest -L bdd` runs nothing | `bdd` is the test name; the label is `functional` | `ctest --test-dir build/Debug -L functional` |
| int8 `check-determinism` with `NESSO_THREADS=$(nproc)` fails and Pipeline stays green | That step is `continue-on-error: true`. The default int8 policy blocks | Drop `NESSO_THREADS` and rerun. fp32 is `--model-dir models-fp32` after `./scripts/fetch-model models-fp32 fp32` |
| `python3 scripts/bench` exits on `/usr/bin/time` or a missing binary | It requires GNU time (`/usr/bin/time` from the `time` package) and a built `nesso` (default `build/Release/src/nesso`). The amd64 build-env image includes that package | Outside that image, install `time` and build Release. A tier that does not finish also exits 1 |
| `conan install --no-remote` misses lockfile packages | The baked cache is `CONAN_HOME=/opt/conan2` inside `nesso-build-env` | Drop `--no-remote` outside that image; keep `--lockfile=conan.lock` |
| `CMakeUserPresets.json` shows in `git status` | `conan install` writes it and `.gitignore` does not list it | Leave it uncommitted |
| A plain `cmake` build uses the compiler default, or a local `gcc-26-debug` run continues after UBSan | `compiler.cppstd` was the only C++ standard, and `gcc-26-debug` had no `-fno-sanitize-recover` | `nesso_options` requires `cxx_std_26` with extensions off. `-Werror` is `NESSO_WERROR`, off unless `conan -c user.nesso:werror=True`. The debug profile stops on the first sanitizer error |
| `prepare-image-amd64`, `prepare-image-arm64`, `prepare-image-el9-amd64`, or `prepare-image-el9-arm64` rebuilds for a long time | `scripts/ci/build-env-hash` inputs changed, including `test/functional/go.sum` and the copied profiles `gcc-26`, `gcc-26-debug`, `gcc-26-armv8`, `gcc-26-el9`, and `gcc-26-el9-armv8` | Expect that job; its timeout is 360 minutes. Consumer-only `user.nesso:*` edits still change the hash |
| SLSA provenance fails when the generator `uses` a commit SHA | `.github/workflows/release.yml` calls those workflows by tag | Keep the `vX.Y.Z` tag. The generator checks its own ref |
| Publishing the Unreleased draft did not publish nesso | That draft's tag name is `unreleased`, which is not `vX.Y.Z`, so `.github/workflows/release.yml` does not run | Bump `version` in `conanfile.py` on `main`, then publish the `vX.Y.Z` draft |
| `eval-retrieval` fails with `WORSE` lines | A nesso ranker's per-query MRR or nDCG@10 got worse beyond noise against the merge base | Fix the ranking, or, when the trade-off is intended, add the label `eval-regression-accepted` and re-run the job |
| Codecov upload warns and `coverage` stays green | `fail_ci_if_error` is false. Forks and Dependabot have no Actions secret. The Codecov GitHub App may be unset, or the org may still require a token for public uploads | Read the `coverage` job log. The floors in `scripts/code-coverage` remain the gate. `.github/codecov.yml` does not add another one |
